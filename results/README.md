# Results

Every number in the report and the presentation comes from these three files. All runs use
the frozen validation split (`val_split.json`, produced by `wpformer_plus.py` and reused
unchanged across every configuration), batch size 4, input 384×384, mixed precision, and a
single NVIDIA T4.

## `ablation.csv`

The six single-variable configurations, each trained for 30 epochs and evaluated once on
the 395-image CrackSeg9k test set. `delta_wF` and `delta_pct` are measured against the
`baseline` row, never against the published paper.

Reproduce any row with:

```bash
python wpformer_plus.py --preset <run> --epochs 30 \
    --data-root /content/data/CrackSeg9k --out-dir runs
```

## `tta.csv`

Test-time augmentation, evaluated on the **fixed** `backbone` checkpoint so that no
difference is attributable to training. `views_unseen_in_training` counts averaged views
whose transformation never occurs in the training pipeline — the repo's augmentation flips
horizontally only and never rescales.

The final two rows differ only in the per-image min–max stretch, and differ in weighted
F-measure by `5e-5`, which is why the report treats that operation as neutral.

```bash
python wpformer_plus.py --preset backbone --eval-only \
    --ckpt runs/backbone/best.pth --tta --tta-views 2 --tta-scales 1.0
```

## `convergence.csv`

Best validation epoch per run, with the last three validation scores. No run peaks before
epoch 27 and two peak on the final epoch, which is the evidence behind the under-training
hypothesis in the report: none of these configurations had converged when training stopped.

## What is not here

Checkpoints (`best.pth`, `state.pt`) and prediction maps are excluded — together they run
to several gigabytes. Both are regenerated by re-running the commands above. The frozen
split is the one artefact that matters for comparability, and it is written to the output
directory on the first run.
